# Архитектура решения

## Контекст

Приложение решает задачу «Нейро-стенографист»: по аудиозаписи разговора получить текст с разделением по говорящим и временными метками. Все этапы выполняются на Android-устройстве, без сети и без внешних сервисов. Разрешение INTERNET в манифесте отсутствует.

## Компоненты

| Компонент | Файл | Назначение |
|---|---|---|
| Интерфейс | `MainActivity.kt` | Jetpack Compose: выбор файла, число говорящих, прогресс, список реплик, экспорт, воспроизведение |
| Состояние и логика экрана | `MainViewModel.kt` | Загрузка моделей при старте, запуск обработки в фоновом потоке, плеер, запуск резюме |
| Декодирование аудио | `AudioDecoder.kt` | Чтение файла из памяти устройства и приведение к 16 кГц, моно |
| Пайплайн распознавания | `SpeechEngine.kt` | Диаризация, формирование реплик, распознавание речи |
| Модели данных и экспорт | `Models.kt` | Реплика, результат, JSON и TXT |
| Локальная LLM | `Summarizer.kt` | Краткое резюме разговора |

## Конвейер обработки

1. **Декодирование.** Файл приводится к 16 кГц, моно, float. Тихие записи нормализуются по громкости.
2. **Диаризация.** pyannote segmentation 3.0 находит участки речи, CAM++ строит эмбеддинги, агломеративная кластеризация группирует их по говорящим. Число говорящих задаётся пользователем или определяется автоматически.
3. **Автоматический режим и защита от раздробления.** Если при автоопределении найдено больше 5 говорящих (признак того, что один голос раздробился), диаризация повторяется с более высоким порогом кластеризации, а в крайнем случае с фиксированным числом говорящих 3. На обычных записях перезапуска не происходит.
4. **Формирование реплик.** Соседние отрезки одного говорящего с паузой до 0,8 с склеиваются. Перекрытие реплик разных говорящих делится пополам, чтобы один фрагмент звука не попал в две реплики. Слишком короткие отрезки (до 0,45 с) отбрасываются.
5. **Распознавание.** Каждая реплика распознаётся моделью GigaAM v3 CTC, которая сразу выдаёт текст со знаками препинания. Реплики длиннее 20 с режутся на части в самом тихом месте. Запас по краям реплики (0,15 с) не заходит на соседнюю реплику. Обрывки без букв и цифр отбрасываются.
6. **Нумерация говорящих** идёт по порядку появления: первый заговоривший это `speaker_1`.
7. **Вывод.** Список реплик отображается в приложении и экспортируется в JSON и TXT.
8. **Резюме (по запросу).** После расшифровки локальная LLM Qwen2.5-0.5B-Instruct пишет краткое содержание. Длинные разговоры режутся на части и пересказываются по частям, затем собираются в итог. LLM не изменяет распознанный текст, поэтому точность расшифровки и скорость (RTF) от неё не зависят.

## Основные технические решения

- **sherpa-onnx** как единый рантайм для ASR и диаризации: готовые Android-биндинги, работа на CPU, модели в формате ONNX.
- **GigaAM v3 с пунктуацией**: русский язык в приоритете, знаки препинания входят в метрику WER, поэтому отдельный этап восстановления пунктуации не нужен.
- **Диаризация до распознавания**: границы реплик и время начала и конца берутся из диаризации, что даёт точные временные метки.
- **Модели внутри APK**: все модели лежат в `assets` без сжатия (`noCompress`), работа возможна без сети с первого запуска.
- **Модели загружаются один раз при старте** в фоновом потоке, чтобы не задерживать обработку записи.
- **Резюме по запросу и в фоне**, чтобы LLM не влияла на время обработки.
- **Колбэк прогресса диаризации не используется**: лямбда-колбэк вызывал падение нативной библиотеки (`NoSuchMethodError`), прогресс диаризации показывается по этапам.

## Зависимости

- sherpa-onnx 2.0.1 (AAR в `app/libs`)
- MediaPipe tasks-genai (локальная LLM)
- Jetpack Compose, Material 3, AndroidX
- Модели: GigaAM v3 CTC (punct, int8), pyannote segmentation 3.0, 3D-Speaker CAM++, Qwen2.5-0.5B-Instruct (int8)

## Безопасность и приватность

- В манифесте нет разрешения INTERNET: приложение не может передать данные по сети.
- Аудио и расшифровка обрабатываются только в памяти устройства и сохраняются в файл только по явной команде пользователя.
- Внешние сервисы, облачные API и удалённые вычисления не используются.
